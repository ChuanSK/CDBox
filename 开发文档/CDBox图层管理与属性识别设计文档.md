# CDBox 图层管理与属性识别设计文档

**版本：** 1.0

**用途：** 供 Codex 进行产品设计、编码实现、测试与后续迭代
**适用范围：** 污水管网及相关构筑物的 CAD 图层管理、图层属性识别、标注、属性编辑、工程量统计

## 1. 设计目标与基本原则

CDBox 不应要求所有外部图纸采用同一种图层名称。系统应采用“**外部名称宽容输入，内部属性统一管理，规范名称可选输出**”的架构：

```text
任意外部图层名
  → 名称归一化
  → 当前图纸/项目/个人规则
  → 通用词典与属性提取
  → 结构化属性
  → 置信度与冲突判断
  → 自动应用或人工确认
  → 标注、属性、统计等功能统一消费
```

核心原则：

1. 图层名称是识别线索，不是唯一数据源。
2. 系统内部必须使用稳定的结构化字段，而不是从标签文本反向猜测。
3. 对名称明确表达的属性自动识别；未表达的属性保持为空；有歧义的属性要求确认。
4. 对象已存在的显式属性优先于图层名称推断。
5. 原图层名称默认不修改，规范化重命名必须预览并由用户确认。
6. 识别规则必须可解释、可回滚、可限定作用范围。

## 2. 标准图层命名体系

### 2.1 通用格式

标准名称使用半角短横线 `-` 分隔，字段顺序固定：

```text
父分类-对象类型或分类-规格-材料-施工或用途-附加属性
```

字段不足时省略，不使用“未知”“默认”等虚假值。内部名称建议使用中文受控词，规格使用统一编码；显示界面可以提供更友好的格式。

禁止在新建标准图层中使用：空格、括号、下划线、逗号、日期、项目名、施工阶段、无明确含义的缩写。旧图层可继续保留，由兼容识别处理。

### 2.2 规格编码

| 业务含义 | 标准编码 | 示例 |
|---|---|---|
| 管线公称直径 | `DN数字` | `DN110`、`DN300` |
| 井或圆形构筑物直径 | `D数字` | `D315`、`D700` |
| 厚度 | `T毫米数` | `T150`、`T200` |
| 混凝土强度 | `C数字` | `C20`、`C25` |
| 容量 | `V数值单位` | `V2m3`、`V5m3` |
| 数量/编号 | `N数字` 或业务编号 | `N2`、`01` |

厚度内部统一为毫米；`15cm`、`0.15m`、`150mm`均归一化为 `T150`。`300`只有在上下文确认是管径时才转换为 `DN300`，不能仅凭数字猜测。

### 2.3 管线

标准格式：

```text
主管-DN规格-管材-埋设或恢复类型
支管-DN规格-管材-埋设或恢复类型
```

示例：

```text
主管-DN200-波纹管
主管-DN300-双壁波纹管-粗砂回填
主管-DN300-波纹管-混凝土恢复
主管-DN300-波纹管-原土回填
支管-DN75-PVC-明管
支管-DN110-PVC-并埋
支管-DN110-PVC-混凝土恢复
```

管材受控词典初始值：`PVC`、`PE`、`HDPE`、`波纹管`、`双壁波纹管`、`钢管`、`铸铁管`、`混凝土管`。

施工/埋设类型受控词典初始值：`并埋`、`明管`、`原土回填`、`粗砂回填`、`中粗砂回填`、`混凝土恢复`、`混凝土包封`、`标准埋设`。`砼恢复`、`砼路面恢复`等作为别名，不作为新标准名称。

### 2.4 检查井、沉泥井与 315 小井

一般井标准格式：

```text
井-井类型-规格-井体材料-井盖材料
```

示例：

```text
井-检查井-D500-砖砌-铸铁盖
井-检查井-D700-混凝土-铸铁盖
井-沉泥井-D700-砖砌-铸铁盖
井-接户井-D315-塑料-混凝土盖
井-阀门井-D700-混凝土-铸铁盖
井-水表井-D500-砖砌-铸铁盖
```

315 小井必须独立表达，推荐使用：

```text
井-315小井-D315-塑料-混凝土盖
```

如果业务上已明确其为接户井，也可以使用：

```text
井-接户井-D315-塑料-混凝土盖
```

“315井”是规格或传统简称，不应自动等同于某一种井型。`315小井`与`接户井`的对应关系由项目规则或用户确认决定。井径不能替代井类型；`700铸铁井盖`只能识别为 `D700 + 铸铁盖`，井类型应标记为缺失或歧义。

井类型初始词典：`检查井`、`沉泥井`、`接户井`、`315小井`、`阀门井`、`水表井`、`跌水井`、`截流井`、`溢流井`、`雨污分流井`、`其他井`。

### 2.5 混凝土及结构层

标准格式：

```text
结构层-材料或强度-厚度-用途
```

示例：

```text
结构层-C25混凝土-T150-路面恢复
结构层-C25混凝土-T200-路面恢复
结构层-C20混凝土-T100-包封
结构层-中粗砂-T100-垫层
结构层-碎石-T150-垫层
结构层-原土回填
```

常见材料：`混凝土`、`中粗砂`、`粗砂`、`碎石`、`级配碎石`、`原土`、`沥青混凝土`、`砖砌体`。强度和厚度分别解析为 `strengthGrade` 与 `thickness`，不能合并为一个标签。

### 2.6 化粪池、隔油池及构筑物

标准格式：

```text
构筑物-类型-规格或容量-材料-用途
```

示例：

```text
构筑物-化粪池
构筑物-化粪池-V2m3-砖砌
构筑物-化粪池-V5m3-混凝土
构筑物-隔油池-V2m3-混凝土
构筑物-隔油池-型号G1-成品
构筑物-蓄水池-V5m3-混凝土
构筑物-泵站-型号P1-混凝土
构筑物-阀门设施-DN200
构筑物-格栅井-D1000-混凝土
构筑物-跌水构筑物
```

构筑物类型初始词典：`化粪池`、`隔油池`、`蓄水池`、`泵站`、`阀门设施`、`格栅井`、`跌水构筑物`、`截流设施`、`溢流设施`、`检查口`、`其他构筑物`。

### 2.7 注记、测点与辅助对象

```text
注记-通用
注记-管线长度-主管
注记-管线长度-支管
注记-节点
注记-工程量
注记-断面
测点-代码
测点-点号
测点-高程
测点-描述
辅助-图框
辅助-辅助线
辅助-临时
```

`ZJ`、`主管注记`、`支管注记`、`测点代码`等旧名称保留为兼容别名；日期、项目名称和施工批次应作为项目/对象属性，不写入标准图层名。

### 2.8 标准名称到内部属性的映射

例如 `井-沉泥井-D700-砖砌-铸铁盖` 应得到：

```json
{
  "parentCategory": "井",
  "objectType": "井",
  "nodeType": "沉泥井",
  "specification": "D700",
  "bodyMaterial": "砖砌",
  "coverMaterial": "铸铁盖",
  "systemTags": ["节点", "D700", "砖砌", "铸铁盖"]
}
```

## 3. 外部个性化图层名兼容方案

### 3.1 识别分层

识别器采用以下顺序：

1. 对象显式属性。
2. 当前图纸人工确认映射。
3. 当前项目规则。
4. 用户个人规则。
5. CDBox 内置标准模板和通用词典。
6. 旧版兼容规则。
7. 通用关键词/数字/单位提取。
8. 项目默认值，仅在明确允许时使用。
9. 未识别或待确认。

同一优先级内按规则优先级、匹配精度、匹配字段数量和规则更新时间排序。高优先级规则命中后可选择“停止”或“继续合并”。

### 3.2 名称归一化

归一化只生成分析文本，不修改原始图层名。处理包括：

- 全角括号转为普通分隔符；
- 中文和英文标点统一；
- 删除无意义空格；
- 中文/英文大小写统一；
- `砼`、`混泥土`归一为 `混凝土`；
- `波纹`按词典映射为 `波纹管`；
- `原土`映射为 `原土回填`时必须受规则范围控制；
- `300管`、`管300`在管线语境中提取为 `DN300`；
- `315井`提取为 `D315`，但井型不自动补齐；
- `15cm`、`150mm`统一为 `T150`。

### 3.3 用户规则类型

| 匹配方式 | 适用场景 |
|---|---|
| 精确匹配 | 已知固定图层名 |
| 包含匹配 | 简单稳定的关键词 |
| 通配符 | 兼容旧版规则 |
| 关键词组合 | 词语顺序不固定，推荐普通用户使用 |
| 模板匹配 | 标准名称或用户固定格式 |
| 正则表达式 | 高级用户的复杂规则 |
| 映射表 | 外部单位编号或项目专用编码 |

关键词组合应支持：必须包含、任一包含、可选包含、必须排除、词组边界和作用对象。例如：

```text
必须包含：300、波纹
任一包含：砼恢复、混凝土恢复、路面恢复
必须排除：注记、文字
输出：父分类=主管；规格=自动提取；材料=波纹管；施工类型=自动提取
```

### 3.4 固定值与自动提取

每个输出字段均应支持四种模式：`固定值`、`自动提取`、`不设置`、`使用默认值`。例如 `300波纹` 可以得到 `DN300 + 波纹管`，但施工类型为空；系统不能因为常见项目习惯而擅自补为“混凝土恢复”。

### 3.5 识别示例

| 外部图层名 | 自动识别结果 | 状态 |
|---|---|---|
| `300波纹管（砼恢复）` | 主管? / DN300 / 波纹管 / 混凝土恢复 | 父分类需依据规则 |
| `波纹管300砼恢复` | DN300 / 波纹管 / 混凝土恢复 | 高可信 |
| `300波纹` | DN300 / 波纹管 | 不完整 |
| `700铸铁井盖` | D700 / 铸铁盖 | 井型歧义 |
| `315井(混凝土)` | D315 / 井盖或井体信息待确认 | 歧义 |
| `污水主干-300` | 主管? / DN300 | 需项目规则确认 |

### 3.6 方案层级

规则和词典按以下范围保存：

```text
当前图纸方案 > 当前项目方案 > 用户个人方案 > 系统内置方案
```

当前图纸方案解决外来图纸，不污染长期配置；项目方案解决某个设计院或项目约定；个人方案解决用户长期习惯；内置方案提供通用能力。任何人工确认都应可选择保存范围。

## 4. 增强后的属性识别表设计

### 4.1 识别规则表

建议字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | ID | 规则唯一标识 |
| `name` | 文本 | 用户可读名称 |
| `enabled` | 布尔 | 是否启用 |
| `scope` | 枚举 | drawing/project/user/system |
| `priority` | 整数 | 数值越大越优先 |
| `matchMode` | 枚举 | exact/contains/wildcard/keywords/template/regex/mapping |
| `matchExpression` | JSON | 匹配条件 |
| `excludeExpression` | JSON | 排除条件 |
| `outputMapping` | JSON | 输出字段与取值模式 |
| `mergeMode` | 枚举 | stop/merge/ask |
| `applicableObjectTypes` | 数组 | 管线、井、构筑物等 |
| `confidenceBase` | 数值 | 规则基础置信度 |
| `source` | 枚举 | system/imported/user/confirmed |
| `createdAt/updatedAt` | 时间 | 审计信息 |

### 4.2 别名词典表

| 字段 | 说明 |
|---|---|
| `canonicalValue` | 标准值，如“混凝土恢复” |
| `alias` | 别名，如“砼恢复” |
| `attributeType` | material、constructionType、nodeType 等 |
| `scope` | 词典作用范围 |
| `caseSensitive` | 是否区分大小写 |
| `boundaryRequired` | 是否要求词边界 |
| `conflictGroup` | 互斥或冲突分组 |
| `enabled` | 是否启用 |

别名不能无条件全局生效。例如 `315井=接户井`应作为项目规则或用户规则，而不是系统通用别名。

### 4.3 属性提取器

内置提取器至少包括：

- 管径：`DN300`、`300管`、`管300`；
- 井径：`D700`、`700井`、`700井盖`；
- 厚度：`T150`、`15cm`、`150mm`；
- 混凝土强度：`C25`；
- 容量：`2m³`、`2m3`；
- 材料、施工类型、井类型、构筑物类型；
- 污水/雨水/合流等系统属性，仅在词典或项目规则明确时提取。

提取结果应带来源区间、规范化值、原始文本和提取器名称，便于解释和调试。

### 4.4 置信度

置信度不是“是否识别成功”的替代品，而是用于排序和人工确认。建议采用可解释的评分项：

```text
总分 = 规则基础分
     + 精确匹配加分
     + 关键词数量加分
     + 字段边界加分
     + 标准单位加分
     - 冲突扣分
     - 缺失必填字段扣分
```

建议状态阈值：

| 分数 | 状态 | 处理 |
|---|---|---|
| 0.90–1.00 | 高 | 可自动应用，保留撤销入口 |
| 0.70–0.89 | 中 | 批量预览后应用 |
| 0.40–0.69 | 低 | 必须人工确认 |
| <0.40 | 未识别 | 不自动写入业务属性 |

置信度必须同时显示“为什么得到这个结果”，例如：命中项目规则、提取 `DN300`、命中别名 `砼恢复`。

### 4.5 冲突与歧义

以下情况进入待确认队列：

- 两条同优先级规则输出不同父分类；
- 同一名称同时命中 `检查井` 和 `沉泥井`；
- 数字无法判断是管径、井径、编号还是厚度；
- 规则输出与对象显式属性冲突；
- 图层中混合对象语义；
- 必填字段缺失且会影响后续功能。

冲突处理策略：保留全部候选、标明来源和分数、推荐最佳候选、要求用户确认；确认后可保存为当前图纸/项目/个人规则。系统不得静默覆盖对象已有属性。

### 4.6 识别结果数据模型

推荐内部模型：

```json
{
  "layerId": "layer-001",
  "rawName": "300波纹管（砼恢复）",
  "normalizedName": "DN300 波纹管 混凝土恢复",
  "parentCategory": "主管",
  "objectType": "管线",
  "category": "DN300",
  "specification": "DN300",
  "material": "波纹管",
  "constructionType": "混凝土恢复",
  "nodeType": null,
  "purpose": null,
  "systemTags": ["DN300", "波纹管", "混凝土恢复"],
  "userTags": [],
  "source": ["project-rule-12", "material-alias-3", "diameter-extractor"],
  "confidence": 0.96,
  "status": "recognized",
  "conflicts": [],
  "needsConfirmation": false
}
```

## 5. 图层管理器增强设计

### 5.1 树形结构

一级分类建议：

```text
主管
支管
井
结构层
构筑物
注记
测点
辅助
未识别
```

二级及以下节点使用结构化字段生成，而不是继续依赖字符串搜索。例如：

```text
主管
├─ DN200
└─ DN300
   └─ 波纹管
井
├─ 检查井
├─ 沉泥井
├─ 315小井
└─ 接户井
```

### 5.2 图层状态

每个图层显示：`规范`、`兼容`、`不完整`、`冲突`、`混合`、`未识别`。状态旁显示置信度、识别来源和待处理原因。

### 5.3 核心操作

- 扫描并识别全部图层；
- 查看原名称、归一化名称和结构化结果；
- 筛选未识别、低置信度、冲突和混合图层；
- 批量确认或修改属性；
- 生成规范名称预览；
- 按用户输出模板生成名称；
- 将确认结果保存为指定范围的规则；
- 应用/撤销识别结果；
- 导入、导出识别方案和词典；
- 查看规则命中解释和变更历史。

重命名应采用：

```text
原名称 → 建议名称 → 影响对象数 → 冲突提示 → 用户确认 → 可撤销执行
```

### 5.4 混合图层检测

扫描图层内对象的显式属性、块名、实体类型和空间对象信息。当同一图层出现多个关键语义组合，例如 `DN110` 与 `DN160`、检查井与沉泥井、并埋与明管，状态标记为“混合”，提供按属性拆分图层的预览功能。拆分属于高影响操作，必须用户确认并支持回滚。

## 6. 用户使用说明

### 6.1 新建标准图层

1. 打开图层管理器，选择父分类。
2. 选择对象类型、规格、材料和施工/用途。
3. 系统按标准模板生成名称，并预览内部属性。
4. 用户确认后创建图层。
5. 如需适配单位习惯，可选择输出名称模板，但内部字段保持标准。

### 6.2 打开旧图或外来图纸

1. 打开图层管理器并执行“扫描识别”。
2. 优先处理高置信度结果，查看命中解释。
3. 对低置信度、冲突或歧义结果逐条确认。
4. 选择确认结果保存范围：仅本图、当前项目或个人规则。
5. 批量应用识别结果；原始图层名默认不变。
6. 如需要，使用“规范化命名”查看并确认重命名预览。

### 6.3 配置属性识别表

1. 在“识别规则”页新增规则。
2. 选择匹配方式；普通用户优先选择“关键词组合”。
3. 填写必须包含、任一包含和排除关键词。
4. 为每个属性选择固定值、自动提取、不设置或默认值。
5. 设置优先级、作用范围和命中后行为。
6. 使用测试区输入若干图层名，检查预览结果。
7. 保存后对当前图纸重新扫描，确认命中数量和误命中数量。

### 6.4 配置别名词典

在“词典与别名”页维护标准值和用户常用写法。例如：

```text
标准值：混凝土恢复
别名：砼恢复、砼路面恢复、混凝土路面恢复
属性：施工类型
范围：当前项目
```

对可能改变业务含义的词，如 `315井`、`原土`、`300波纹`，必须限定范围或配置附加条件。

### 6.5 识别结果确认

确认界面至少显示：原图层名、归一化名称、候选结果、置信度、命中规则、缺失字段、冲突原因和保存范围。用户可以选择接受、修改、忽略、创建规则或标记为不适用。

## 8. 识别流程与伪代码

```text
scanLayers(drawing):
  layers = loadLayers(drawing)
  for layer in layers:
    objects = inspectObjects(layer)
    explicit = readExplicitObjectAttributes(objects)
    normalized = normalizer.normalize(layer.name)
    candidates = []
    for plan in plansByPriority(currentDrawing, project, user, system):
      candidates += matcher.match(plan.rules, layer.name, normalized, objects)
    extracted = extractor.extract(normalized, vocabulary)
    candidates += combine(candidates, extracted)
    result = scorer.rankAndMerge(candidates, explicit)
    result.status = statusOf(result)
    result.conflicts = detectConflicts(result, explicit, objects)
    savePreview(layer.id, result)
  return previews
```

原则：识别预览与实际写入分离；低置信度不自动补齐；人工确认产生审计记录；对象已有属性不被图层结果静默覆盖。

## 9. 迁移与兼容策略

### 9.1 旧规则兼容

保留现有“包含”和“通配符”规则的读取能力，并在导入时转换为兼容规则。旧规则不应自动获得高于项目/个人明确规则的优先级。

### 9.2 旧图层兼容

原始名称永久保留；增加内部识别结果和可选规范名称。迁移时先生成报告：识别成功数、部分识别数、冲突数、未识别数和建议规则。用户确认后再写入属性或重命名。

### 9.3 规则版本化

识别方案、词典和规则均保存版本号。每次批量应用记录图纸、方案、规则、操作者、时间、修改对象数和回滚信息。导入外部方案时进行命名空间隔离，避免覆盖现有规则。

### 9.4 数据优先级

```text
对象显式属性
  > 当前图纸确认映射
  > 当前项目规则
  > 用户个人规则
  > 系统内置规则
  > 默认值
```

冲突时提示用户，不做静默覆盖。

## 10. 验收标准

### 10.1 标准命名

- 能创建主管、支管、检查井、沉泥井、315 小井、结构层、化粪池、隔油池等标准图层。
- 能解析 `DN`、`D`、`T`、`C`、容量等字段。
- 井类型与井径独立存储；315 小井不会仅凭数字被错误归类。
- 混凝土、化粪池、隔油池归入正确父分类。

### 10.2 兼容识别

- `300波纹管（砼恢复）`、`波纹管300砼恢复`可识别为相同的规格、材料和施工类型。
- `300波纹`只识别已表达的属性，不擅自补齐施工类型。
- `700铸铁井盖`提示井类型缺失或歧义。
- 全角标点、空格、大小写、常见同义词可归一化。
- 可限定规则和词典的作用范围。

### 10.3 识别表

- 支持精确、包含、通配符、关键词组合、模板和正则匹配。
- 支持固定值与自动提取的组合输出。
- 支持优先级、排除条件、命中停止/合并/询问。
- 每个结果显示来源、置信度、缺失字段和冲突原因。
- 人工确认可保存为当前图纸、项目或个人规则。

### 10.4 图层管理器

- 能按结构化字段建立树形分类。
- 能筛选规范、兼容、不完整、冲突、混合和未识别状态。
- 规范化重命名具有预览、确认、审计和撤销能力。
- 混合图层可被检测并提供拆分预览。

### 10.5 回归测试集

至少建立以下测试样本：

```text

```

验收不仅检查“是否命中”，还要检查：是否错误补齐、是否正确报告歧义、是否保留原名、是否能解释来源、是否能撤销批量应用。

## 11. 实施优先级

### P0：识别基础

1. 结构化属性模型。
2. 名称归一化与内置词典。
3. 标准模板解析。
4. 当前识别表规则兼容。
5. 识别预览、置信度、冲突和人工确认。

### P1：管理器增强

1. 结构化树形分类。
2. 状态筛选与批量确认。
3. 规范名称预览与可撤销重命名。
4. 方案层级与规则导入导出。

### P2：高级能力

1. 混合图层检测与拆分。
2. 一次确认生成规则建议。
3. 识别质量统计与规则命中分析。
4. 面向工程量、标注、断面和属性编辑的统一字段服务。

## 12. 最终产品结论

CDBox 应将“标准图层命名”定位为可靠、可读的推荐输出格式，将“属性识别表”升级为可解释的规则与词典系统，将“图层管理器”升级为识别、确认、治理和迁移入口。最终所有下游功能只读取结构化属性：

```text
图层名称只是输入线索
结构化属性才是系统事实
人工确认是处理歧义的闭环
规范名称是可选的治理结果
```

这样既能支持最规范的新建图纸，也能兼容用户个性化命名、旧图纸和外来图纸，并为后续标注、属性编辑、断面生成和工程量统计提供一致的数据基础。
