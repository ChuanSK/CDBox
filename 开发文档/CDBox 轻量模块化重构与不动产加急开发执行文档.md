# CDBox 轻量模块化重构与不动产加急开发执行文档

## 1. 文档定位

开始本轮开发前，必须首先完整阅读：

**《CDBox 多业务模块架构重构构建文档》**

该文档描述的是 CDBox 长期多业务模块化的目标架构、模块边界、依赖原则、稳定性要求以及未来演进方向。

但是必须特别注意：

> **本轮开发的终点不是完成《CDBox 多业务模块架构重构构建文档》中描述的完整重构。**

当前存在明确的业务时间压力：

> 不动产业务将在未来几周内进入大规模实际生产阶段。

因此，本轮工作的核心目标已经由：

> “完成 CDBox 多业务模块架构重构”

调整为：

> **“用最低风险建立足够的不动产模块边界，然后立即进入不动产业务开发，并尽快形成可投入真实生产的不动产功能。”**

上一份文档是：

**长期架构蓝图。**

本文件是：

**当前阶段实际执行方案。**

如果二者在“当前应该重构到什么程度”上发生冲突：

> **以本文件为准。**

# 2. 本轮最高目标

本轮工作只服务于两个目标。

## 目标 A：保护现有 CDBox

必须保证现有：

- 污水主管；
- 支管；
- 检查井；
- 沉泥井；
- 属性编辑；
- 属性识别；
- 默认表；
- 起终点识别；
- 深度联动；
- 结构层；
- 工程量；
- 标注；
- 图层管理；
- WebView2 页面；
- 公共工具；
- 更新系统；
- 设置；
- 旧图纸兼容；

不因为此次模块化准备工作出现明显退化或崩溃。

## 目标 B：尽快开始不动产开发

轻量重构完成后：

> **立即停止继续拆分现有架构，进入 CDBox 不动产模块开发。**

不得因为：

- Core 还不够纯净；
- UI 尚未彻底拆分；
- Wastewater 尚未独立程序集；
- Common 尚未完全整理；
- 旧 namespace 尚未统一；
- ModuleManager 尚不够完善；

而继续推迟不动产功能开发。

# 3. 当前开发思想

本轮采用：

> **最小可行模块化（Minimum Viable Modularization）**

而不是：

> 完整平台重构。

核心原则：

> **先建立边界，不立即整理内部。**

即：

```
当前 CDBox
│
├── 现有污水及既有功能
│      尽量保持原状
│
├── 最小公共能力层
│
└── 新建 RealEstate 不动产模块
```

现有 CDBox 即使暂时仍然包含：

```
Legacy
+
Wastewater
+
部分 Common
+
部分 Platform
```

也是允许的。

本轮不追求架构最终形态。

# 4. 必须明确理解的长期架构与当前架构区别

长期目标仍然是：

```
CDBox Platform
│
├── Core
├── Cad
├── UI
├── Common
│
├── Wastewater
└── RealEstate
```

但是：

## 本轮禁止为了达到上述结构而强制完成全部拆分。

当前允许采用：

```
CDBox
│
├── 现有代码
│   ├── 污水业务
│   ├── CAD 基础
│   ├── UI
│   └── 部分公共功能
│
├── CDBox.Shared
│
└── CDBox.RealEstate
```

甚至如果进一步拆分会明显增加风险：

```
CDBox.Shared
```

也只需要包含当前确实需要共享的内容。

# 5. 本轮重构时间必须受控

轻量重构不是一个开放式任务。

建议目标：

> **2～4 个有效开发日完成。**

如果达到以下最低条件：

- RealEstate 已拥有独立代码边界；
- 不动产能够使用统一 UI；
- 不动产能够使用日志；
- 不动产能够安全调用必要 CAD 公共能力；
- 不动产能够使用需要的公共工具；
- RealEstate 不依赖污水业务；
- 现有污水功能没有明显退化；

则：

> **立即判定轻量重构完成。**

即使完整架构仍然很不理想，也必须停止继续重构。

# 6. 本轮严禁出现“重构惯性”

Codex / Work 很容易在发现旧代码结构存在问题后继续进行：

```
既然已经拆了 Shared
↓
顺便拆 Core
↓
顺便拆 Cad
↓
顺便拆 UI
↓
顺便把 Wastewater 全部迁移
↓
顺便统一 namespace
↓
顺便改 Service
↓
顺便重做 ModuleManager
```

这是本轮明确禁止的行为。

遇到这种情况必须重新回到当前目标：

> **这项修改是否是不动产立即开发所必需？**

如果答案为：

**否**

则：

> 不做。

记录为后续技术债即可。

# 7. 本轮不对污水业务进行正式模块迁移

这是最重要的风险控制要求之一。

即使长期目标存在：

```
CDBox.Wastewater
```

本轮也不要求建立完整 Wastewater 独立模块。

尤其禁止大规模：

- 移动污水业务文件；
- 修改污水 namespace；
- 修改污水 Service；
- 修改污水模型；
- 修改属性保存逻辑；
- 调整 XData；
- 调整 ExtensionDictionary；
- 调整对象标识；
- 重写节点—管线联动；
- 重构工程量；
- 重构结构层；
- 重构标注。

当前原则：

> **污水业务能不动就不动。**

# 8. 允许的污水侧修改

只有以下情况可以修改污水侧代码：

### 情况 1

为了抽取一个 RealEstate 同样必须使用的公共能力。

例如：

```
Toast
Logging
WebView Host
Excel
Template
CAD Selection Helper
```

### 情况 2

为了消除 Shared 对 Wastewater 的反向依赖。

例如发现：

```
ExcelService
↓
MainPipe
```

需要最低限度解除耦合。

### 情况 3

编译所必需。

除此之外：

> 不修改污水业务。

# 9. 第一阶段：建立安全基线

开始任何修改前：

必须建立当前稳定基线。

至少保留：

```
当前源码
当前可运行 DLL
当前配置
典型污水测试 DWG
当前安装结构
```

建议建立 Git Tag：

```
pre-realestate-light-refactor
```

或者等价稳定分支。

必须保证：

> 任何时候都能够快速恢复到当前稳定 CDBox。

# 10. 第二阶段：建立 RealEstate 项目边界

建立独立：

```
CDBox.RealEstate
```

或者：

```
CDBox.Modules.RealEstate
```

本轮名称可根据现有 Solution 风格确定。

至少包含：

```
RealEstate
├── Module
├── Commands
├── Models
├── Services
└── UI
```

此时可以暂时只有空实现。

最重要的是建立：

> **以后所有不动产业务代码都必须进入该边界。**

禁止继续把地籍代码直接写进现有污水或主业务目录。

# 11. RealEstate 不允许依赖 Wastewater

必须确保：

```
RealEstate
↓
公共能力
```

而不是：

```
RealEstate
↓
Wastewater
```

例如不允许：

```
RealEstate
→ MainPipeService
```

即使某个污水 Service 恰好已经提供了类似功能，也不能直接使用。

应该：

```
提取真正公共部分
```

或者：

```
RealEstate 单独实现业务部分
```

# 12. 第三阶段：仅提取 RealEstate 立即需要的公共能力

不要预先设计完整 Core。

只处理不动产即将用到的内容。

初步预计可能包括：

```
Logging
Config
Toast
Dialog
WebView2 Host
Template
Excel
CAD Selection
Transaction Helper
Polyline Geometry
Layer Helper
Entity Helper
```

但：

> 实际没有立即使用的，不要为了架构完整而迁移。

# 13. Shared 的定位

本轮可以建立：

```
CDBox.Shared
```

它是：

> **过渡期公共基础层。**

不是最终架构。

因此允许暂时同时存在：

```
UI 基础
Core Utility
CAD Helper
公共 Service
```

不需要立即细分：

```
Core
Cad
UI
Common
```

后续业务压力下降后再拆。

# 14. Shared 的依赖红线

允许：

```
CDBox
↓
Shared
```

允许：

```
RealEstate
↓
Shared
```

禁止：

```
Shared
↓
Wastewater
```

禁止：

```
Shared
↓
RealEstate
```

Shared 内不得出现：

```
MainPipe
BranchPipe
InspectionWell
Parcel
BoundaryPoint
Building
```

等具体专业业务对象。

# 15. 不要求立即迁移全部公共代码

例如当前 Toast 已经存在于 CDBox 内。

如果将 Toast 完整迁移 Shared 会牵连大量页面：

不要一次迁移全部。

可以建立：

```
IToastService
```

或者：

```
Shared Toast Facade
```

通过兼容层继续调用原实现。

原则：

> **优先桥接，谨慎搬迁。**

# 16. “先包起来，再拆开”仍然适用

例如：

```
LegacyWebViewHost
```

已经稳定。

不要为了 RealEstate 重写。

可以：

```
IWebViewHost
      ↓
LegacyWebViewHost
```

RealEstate 使用接口。

未来再替换内部实现。

# 17. 第四阶段：建立不动产入口

RealEstate 必须拥有独立业务入口。

用户层面应逐渐形成：

```
CDBox

CDBox 不动产
```

不要求现阶段完成最终菜单设计。

但必须避免：

> 不动产所有功能继续直接堆入当前 CDBox 主业务菜单。

# 18. UI 必须保持 CDBox 风格一致

虽然 RealEstate 是独立业务模块，但必须复用 CDBox 的：

- WebView2；
- 窗口；
- 主题；
- Toast；
- Dialog；
- Loading；
- 动画；
- 基础组件；
- 提示方式。

原则：

> **业务独立，体验统一。**

禁止为 RealEstate 重新开发第二套视觉系统。

# 19. RealEstate 初始生命周期只做最小实现

允许简单：

```
RealEstateModule.Initialize()
```

负责：

```
注册命令
注册页面
初始化必要 Service
```

本轮不要求完成复杂的：

```
动态 DLL 扫描
热加载
热卸载
第三方插件体系
模块依赖图
复杂 DI
```

# 20. ModuleManager 只做最小版本

如果需要 ModuleManager：

第一版允许：

```
Register(new RealEstateModule());
```

甚至当前污水业务暂时不注册为正式 Module 也可以。

不要因为：

```
Wastewater 还不是标准 Module
```

而阻塞 RealEstate。

# 21. RealEstate 加载失败不得拖垮现有 CDBox

RealEstate 初始化应存在独立异常保护。

例如：

```
CDBox 加载
│
├── 现有功能正常
│
└── RealEstate 初始化
        ↓
       ERROR
```

结果必须是：

```
现有 CDBox 继续运行
RealEstate 被禁用
记录日志
提示加载失败
```

不能：

```
RealEstate ERROR
↓
整个 CDBox 无法加载
```

# 22. 不要提前重构 Update 系统

长期需要支持模块化更新。

但：

> **本轮不以模块独立更新为前置条件。**

如果现有 updater 可以继续：

```
整体更新 CDBox
```

则继续使用。

只要安装包能够包含：

```
CDBox.RealEstate.dll
```

即可。

模块独立版本和增量更新属于后续优化。

# 23. 不要提前重构配置系统

如果现有：

```
Config
Settings
```

仍然可用：

继续使用。

RealEstate 可以拥有自己的：

```
RealEstateSettings
```

但无需立即重做所有设置层级。

禁止：

> 为了实现不动产设置，顺便迁移所有旧 CDBox 配置。

# 24. 不要提前重构 WebView 路由

如果现有：

```
studio|action|args
```

等消息体系仍可用：

可以在兼容基础上增加 RealEstate 路由。

例如：

```
realestate|action|args
```

或者：

```
cdbox|realestate|action|args
```

具体形式根据现有实现选择。

不得要求：

> 先把所有旧页面迁移到新协议，再开发不动产。

# 25. 轻量重构完成条件

满足以下条件即可立即结束架构阶段：

## 代码边界

存在：

```
CDBox.RealEstate
```

不动产拥有独立代码空间。

## 公共能力

RealEstate 可以使用：

```
日志
UI
必要 CAD API
必要公共工具
```

而无需直接调用污水业务。

## 现有稳定性

原有污水主要流程能够正常：

```
识别
编辑
联动
刷新
工程量
```

## 故障隔离

RealEstate 初始化失败不会导致原 CDBox 整体崩溃。

只要以上四点成立：

> **轻量重构完成。**

不要继续重构。

# 26. 轻量重构完成后立即切换任务目标

从此刻开始，主要任务必须从：

```
Architecture
```

切换为：

```
RealEstate Production
```

也就是：

> **真正开始做不动产业务。**

之后只有当架构问题直接阻塞某项不动产功能时，才允许继续调整 Shared / Platform。

# 27. 不动产第一阶段目标

本文件不定义完整不动产业务实现方案。

具体业务功能应单独建立开发文档。

这里只定义当前阶段方向：

> **第一阶段不是建立完整的不动产信息系统，而是尽快形成能够支持公司当前真实不动产生产任务的工具。**

优先级：

```
真实项目能用
>
减少人工工作
>
结果可靠
>
批量处理
>
自动化程度
>
架构完整度
```

# 28. 第一版应围绕现有真实生产流程

不得先凭理论开发大量未来功能。

开发过程中应持续使用：

```
公司真实 CASS 图纸
+
公司实际调查表模板
+
实际作业流程
```

进行验证。

目标是：

> 不动产模块第一批功能一旦完成，就能够直接拿真实项目测试。

# 29. 第一阶段业务开发原则

优先实现：

```
已有数据
↓
自动读取
↓
自动计算
↓
自动填充
↓
人工确认少量无法确定内容
↓
生成成果
```

而不是追求：

```
全部自动判断
```

如果某个复杂自动识别功能需要大量时间：

第一版允许：

```
自动识别失败
↓
用户确认
↓
继续生成
```

生产效率优先。

# 30. 自动化必须允许人工确认

不动产业务涉及大量实际权属和成果资料。

因此：

> **系统不确定时不得猜。**

应该形成：

```
已自动确认
待用户确认
缺失
异常
```

等明确状态。

第一版只要：

> 自动完成确定内容，并把不确定内容集中给用户确认，

就已经具有很高生产价值。

# 31. 不动产开发不得反向侵入污水系统

例如开发地籍过程中需要：

```
Polyline 选择
面积
Excel
模板
```

应该：

```
RealEstate
↓
Shared / Common
```

不得：

```
RealEstate
↓
借用某个 MainPipe 工具
```

这种“暂时能用”的依赖以后会成为最严重的技术债。

# 32. 公共功能的处理原则

如果 RealEstate 需要一个已有 CDBox 功能，例如：

```
Excel → CAD
```

有三种处理方式。

优先级如下：

### 第一选择

直接通过已存在且独立的公共接口调用。

### 第二选择

建立薄 Facade / Adapter，让两个业务都能调用现有实现。

### 第三选择

在确认风险较低后，把真正公共实现移动至 Shared/Common。

禁止：

> RealEstate 复制一份相同代码。

# 33. 不动产代码自身必须保持良好边界

虽然整体架构本轮不彻底重构，但：

> **新写的不动产代码从第一天开始必须保持干净。**

至少区分：

```
Models
Services
Cad
UI
Commands
Export
```

不要再制造一个新的“大型单体”。

# 34. RealEstate 数据模型不得依赖 UI

例如未来：

```
Parcel
BoundaryPoint
BoundarySegment
Building
```

等对象不得：

```
引用 WebView2
引用 Form
直接弹 Toast
```

业务数据层必须能够独立运行。

# 35. RealEstate 业务计算不得依赖 Word

未来即使需要生成调查表：

应保持：

```
CAD / 用户数据
↓
RealEstate 数据模型
↓
业务结果
↓
模板输出
```

而不是：

```
CAD
↓
直接找到 Word 单元格
↓
写值
```

本轮即使业务加急，也不能把 Word 模板本身做成业务数据库。

# 36. 真实生产优先于架构扩展

开发过程中如发生冲突：

### A

继续优化 ModuleManager 需要 2 天。

### B

完成一个公司下周就要用的不动产核心功能需要 2 天。

必须选择：

> B。

例如本轮可以接受：

Shared 暂时比较宽
```

可以接受：

可以接受：

```

```

但不接受：

```

```

不接受：

```

```

```

即使开发加急，也不得采用：

```

↓
最后统一编译
```

应继续：

```

验证
↓

```

尤其是：

Reference

WebView
CAD Transaction

相关修改。

# 39. 污水 Smoke Test 必须保留

架构阶段：

每次关键修改都执行污水 Smoke Test。

进入 RealEstate 业务开发后：

如果本次提交：

```
只修改 RealEstate
```

可以不执行完整污水回归。

但如果修改：

```
Shared
Cad Helper
WebView Host
Excel
Config
Update
```

等公共层：

必须重新进行污水 Smoke Test。

# 40. 回归测试最低项目
