# CDBox 工程量属性编辑器与工程量统计实现逻辑

> 用途：供 Codex 开发或重构属性编辑器、工程量统计页面、WebView2 页面及相关 C# 服务时使用。  
> 本文描述的是当前已确认的业务规则和交互规则。界面可以重做，但业务含义、数据来源、联动关系和工程量公式不能被前端自行简化或重新解释。

---

## 1. 文档目标

CDBox 工程量模块不是普通表单，而是四类逻辑的组合：

1. **对象识别**：根据图层管理器中的父属性、分类、标签判断主管、支管、井，并识别管径、井规格、支管类型和主管起终点井。
2. **工程量属性**：属性保存在 CAD 对象自身；主管、支管、井共用底层模型，但显示不同编辑界面。
3. **实时联动**：修改井深、管线垫层、起终点深度、结构层、管径等任一值时，所有相关派生值必须同步更新。
4. **工程量统计与导出**：当前正式工程量表只统计主管和井；Excel 通过固定模板填充。

---

## 2. 最高优先级规则

### 2.1 主管深度字段的定义

主管属性中的：

- `StartDepth`：起点管线开挖深度；
- `EndDepth`：终点管线开挖深度；
- `AverageDepth`：主管平均开挖深度。

它们不是井深本身。

正常检查井端：

```text
端点管线开挖深度 = 相连井的井深 + 当前主管的管线垫层厚度
```

沉泥井端：

```text
500 沉泥井：
端点管线开挖深度
= 相连井井深 + 当前主管管线垫层厚度 - 500沉泥井扣减深度

700 沉泥井：
端点管线开挖深度
= 相连井井深 + 当前主管管线垫层厚度 - 700沉泥井扣减深度
```

默认扣减：

```text
500 沉泥井：0.20m
700 沉泥井：0.50m
```

主管平均开挖深度：

```text
起终点均有效：
AverageDepth = (StartDepth + EndDepth) / 2

只有一个端点有效：
AverageDepth = 有效端点深度

两个端点均无效：
AverageDepth = 0
```

禁止再次在平均深度上叠加管线垫层，因为 `StartDepth`、`EndDepth` 已经包含管线垫层。

### 2.2 井深字段的定义

井属性中的 `WellDepth` 是：

```text
从井口/地表控制位置到“井下方垫层上表面”的深度
```

井下方垫层位于用户填写井深以下。

```text
井真实开挖总深度 = WellDepth + 井下层厚度
```

井结构层自动计算时：

```text
井深范围内可分配高度 = WellDepth
```

标记为“井下层”的层在 `WellDepth` 以下，不参与井深范围内非锁定层的扣减或分配。

示例：

```text
WellDepth = 0.46
承压盖板C25基础 = 0.30，锁定
承压盖板碎石垫层 = 0.10，锁定
中粗砂回填 = 非锁定
中粗砂垫层 = 0.10，锁定，井下层
```

正确结果：

```text
中粗砂回填 = 0.46 - 0.30 - 0.10 = 0.06
真实开挖总深度 = 0.46 + 0.10 = 0.56
```

### 2.3 结构层和深度必须双向联动

当前业务要求：

```text
任何依赖字段改变
→ 立即重新计算所有派生字段
→ 界面展示同步更新
```

刷新按钮仍保留，但它执行完整识别和全量归一化，不是日常联动的唯一入口。

### 2.4 前端不得独立实现工程量公式

WebView2/HTML/JavaScript 只负责展示、收集输入、触发动作和显示校验。工程量计算、对象识别、结构层分配、默认表合并、数据刷新必须由 C# 业务服务统一处理。

## 3. 命令与入口

### 3.1 `SX`：工程量属性编辑器

#### 单对象

```text
预选一个对象或执行 SX 后点选一个对象
→ 严格识别对象类型
→ 打开主管、支管或节点/检查井的小型属性界面
```

#### 多对象

```text
预选多个对象或执行 SX 后点选/框选多个对象
→ 严格过滤有效对象
→ 对每个有效对象套用对应默认表
→ 同步默认表控制字段
→ 执行完整刷新
→ 写回属性
```

多对象模式不打开单对象表单。

### 3.2 `SXMRB`：属性默认表

包含：

- 主管默认表；
- 节点/检查井默认表；
- 支管默认表。

默认表不保存对象身份字段，例如井编号、主管起终点井、CAD Handle、自然标高等。

### 3.3 `SXQC` / `CDQTYCLEAR`：清除属性

支持点选或框选多个对象，删除对象 ExtensionDictionary 中的工程量 Xrecord。清除时不要求对象仍能识别为主管、支管或井，以便清理历史误写属性。

### 3.4 `GCL`：生成正式工程量表

```text
执行 GCL
→ 用户选择统计范围
→ 读取范围内已保存属性且 Enabled=true 的对象
→ 生成主管和井工程量
→ 读取固定 xls 模板
→ 在合计行上方插入 N 条数据行
→ 填入数据
→ 保存为“图纸标题 + 工程量计算表.xls”
```

当前正式 GCL 暂不统计支管。

## 4. 属性保存方式

### 4.1 保存位置

```text
Entity.ExtensionDictionary
└─ Xrecord: CDBoxQuantityPipeAttributes
```

所有读写统一经过 `QuantityPipeAttributeService`，新界面不得绕过服务直接写数据库。

### 4.2 版本

保留 `SchemaVersion`，用于旧属性迁移。

### 4.3 精度

长度、深度、高度、宽度、结构层厚度、面积、体积、工程量结果统一显示和输出两位小数。内部计算可保持 double 全精度。

## 5. 严格对象识别规则

### 5.1 主管

必须同时满足：

```text
图层父属性 == “主管”
对象为 Curve 类对象
```

### 5.2 支管

必须同时满足：

```text
图层父属性 == “支管”
对象为 Curve 类对象
```

### 5.3 井

必须满足：

```text
图层父属性 == “井”
图层分类属于“检查、沉泥井”体系
```

有效分类至少包括：

- 检查；
- 检查井；
- 沉泥井。

实体通常为 BlockReference、Circle、DBPoint 或节点标注逻辑认可的井实体。

### 5.4 无关对象

不得写入属性：

- 普通文字；
- 标注；
- 引线；
- 辅助线；
- 普通图块；
- 父属性未设置；
- 父属性不是主管、支管、井；
- 父属性为井但分类不属于检查/沉泥井。

单对象识别失败时不打开界面；批量时跳过且不计普通失败。

## 6. 图层元数据与规格识别

每次新建属性、按默认表重填、刷新和批量刷新时读取：

- 图层父属性；
- 图层分类；
- 图层标签；
- 图层名称。

优先使用图层管理器正式数据源。

### 6.1 管线规格

从标签、分类、图层名识别：

- `DN110`；
- `DN200`；
- `110PVC`；
- `75PVC`；
- `160PVC`；
- `300HDPE`；
- `φ200`。

同时更新：

```text
Diameter
PipeOuterDiameter
```

例如：

```text
DN200 → 0.20m
DN300 → 0.30m
```

若元数据可识别规格，刷新时使用识别结果；无法识别时保留人工值。

### 6.2 井规格

支持：

- `500检查井`；
- `φ500`；
- `500沉泥井`；
- `700沉泥井`；
- `700砖砌井`。

统一输出建议为 `φ500`、`φ700`。

## 8. 主管属性

### 8.1 字段

| 字段 | UI 名称 |
|---|---|
| 有效长度 | 管线长度(m) |
| `Material` | 管材 |
| `Diameter` | 规格/管径 |
| `StartNode` | 起点井 |
| `EndNode` | 终点井 |
| `StartDepth` | 起点深度(m) |
| `EndDepth` | 终点深度(m) |
| `AverageDepth` | 平均深度(m) |
| `TrenchWidth` | 开挖宽度(m) |
| `RoadThickness` | 原路面结构层(m) |
| `ExcavationType` | 开挖方式 |
| `BackfillType` | 回填类型 |
| `BackfillStructure` | 回填结构层 |
| `PipeOuterDiameter` | 管道外径(m) |
| `DeductPipeVolume` | 扣除管身体积 |

有效长度：

```text
UseManualLength=true 且 ManualLength>0：
EffectiveLength = ManualLength
否则：
EffectiveLength = CAD Curve Length
```

`StartNode`、`EndNode` 保存井编号，当前属于可重新识别的弱绑定。

有相连井时：

```text
StartDepth / EndDepth
= 井 WellDepth
+ 当前主管管线垫层
- 沉泥井扣减
```

`AverageDepth` 是派生值：

```text
AverageDepth = Average(StartDepth, EndDepth)
```

即使界面保留可编辑控件，起终点或结构层变化、刷新、确认前归一化时都会重新计算。

### 9.1 字段

| 字段 | UI 名称 |

### 9.2 支管类型识别

- 砼恢复；
- 并埋；
- 明管；
- 原土回填。

识别优先级建议：

```text
原土回填 > 并埋 > 明管 > 砼恢复
```

### 9.3 支管类型规则

#### 砼恢复

```text

BackfillType = 中粗砂回填

```

禁止用硬编码内置三层模板覆盖用户默认表。

#### 并埋

```text
BranchIncludeInCalculation = false
BackfillType = 无结构层
BackfillStructure = 空
```

#### 明管

```text
BranchIncludeInCalculation = false
BackfillType = 无结构层
BackfillStructure = 空
```

#### 原土回填

```text
BranchIncludeInCalculation = true
BackfillType = 原土回填
结构层仅一层：
名称 = 原土回填
高度 = BranchDepth
标记为管线层
```

修改 `BranchDepth` 时，该层高度实时同步。

## 11. 结构层统一模型

每层至少包含：

| 字段 | 含义 |
|---|---|
| `Name` | 层级名称 |
| `Height` | 高度，单位 m |
| `Locked` | 是否锁定高度 |
| `IsPipeLayer` | 主管/支管中是否为管线所在层 |
| `IsBelowWellLayer` | 井中是否为井下层 |

底层若复用同一布尔字段，UI 和业务语义仍必须区分：

```text
主管/支管：管线层
井：井下层
```

### 11.1 层级操作

保留：

- 添加层；
- 删除层；
- 上移；
- 下移；
- 自动计算。

每层只显示：

- 名称；
- 高度；
- 锁定；
- 管线层/井下层。

### 11.2 自动计算基本规则

```text
TotalHeight = 当前对象结构层分配总高
LockedSum = 参与总高计算的锁定层高度总和
UnlockedCount = 参与计算的非锁定层数量
Remaining = TotalHeight - LockedSum
```

若有非锁定层：

```text
每个非锁定层高度 = Remaining / UnlockedCount
```

若结果为负：

- 保留负数；
- 提示计算异常；
- 不强制改成 0；
- 允许用户自行调整。

### 11.3 主管总高

```text
TotalHeight = AverageDepth
```

### 11.4 支管总高

```text
TotalHeight = BranchDepth
```

原土回填支管固定为一层原土回填，高度直接等于 `BranchDepth`。

### 11.5 井总高

```text
TotalHeight = WellDepth
```

井下层：

- 不计入 `LockedSum`；
- 不参与 `Remaining` 分配；
- 高度保留用户值；
- 只用于井真实开挖总深度。

### 11.6 管线层高度校验

```text
管线所在层高度 > PipeOuterDiameter
```

若不满足：

- 提示；
- 保留错误结果；
- 不强制修正；
- 数据质量模块记录异常。

## 12. 实时联动规则

新界面必须建立依赖图，而不是分别监听几个输入框。

### 12.1 主管：修改起点/终点深度

```text
StartDepth/EndDepth 改变
→ 重算 AverageDepth
→ 用新 AverageDepth 重算非锁定结构层
→ 校验管线层高度
→ 更新工程量预览
```

### 12.2 主管：修改结构层

1. 解析新结构层；
2. 获取当前主管管线垫层；
3. 若已识别起终点井，从井属性绝对重算 `StartDepth/EndDepth`；
4. 若无法取得井属性，可按管线垫层变化量调整现有端点深度；
5. 重算 `AverageDepth`；
6. 以新平均深度重新计算非锁定层；
7. 再次检查自动分配是否改变管线垫层；
8. 必要时二次重算端点深度和平均深度；
9. 更新工程量预览。

### 12.3 主管：修改管径/外径

```text
Diameter 改变
→ 解析 PipeOuterDiameter
→ 校验管线层高度
→ 重算管身体积
→ 更新回填扣减量
```

### 12.4 主管：修改起点井/终点井

```text
井编号改变
→ 查找井属性
→ 重算对应端点深度
→ 重算 AverageDepth
→ 重算非锁定结构层
```

### 12.5 井：修改井深

```text
WellDepth 改变
→ 重算井深范围内非锁定结构层
→ 不扣除井下层
→ 更新真实开挖总深度
→ 更新井工程量预览
```

确认写入后刷新引用该井编号的主管。

### 12.6 井：修改井下层

```text
井下层高度改变
→ 不改变井深范围内非锁定层
→ 改变井真实开挖总深度
```

主管端点深度使用主管管线垫层，不使用井下层。

### 12.7 井：修改井规格

```text
WellSpec 改变
→ 重算井直径/半径
→ 重算井面积
→ 选择沉泥井扣减规则
→ 更新井工程量
→ 更新相关主管端点沉泥扣减
```

### 12.8 支管：修改类型

```text
砼恢复：
载入用户支管默认结构层

并埋/明管：
清空结构层
取消加入计算

原土回填：
建立一层原土回填
高度=BranchDepth
加入计算
```

### 12.9 支管：修改开挖深度

```text
BranchDepth 改变
→ 更新非锁定结构层
```

原土回填时：

```text
唯一“原土回填”层高度 = BranchDepth
```

## 13. 属性编辑器按钮

### 13.1 关闭

- 不写入对象；
- 丢弃未确认修改；
- 不触发跨对象刷新。

### 13.2 确认

```text
收集 UI 值
→ 最终依赖归一化
→ 保存对象 Xrecord
→ 若为井则刷新相关主管
→ 成功后关闭
```

失败时保留界面和输入。

### 13.3 刷新

刷新是全量业务刷新，必须包括：

1. 重新读取图层父属性、分类、标签、图层名；
2. 严格确认对象类型；
3. 根据元数据重新识别管径/井规格；
4. 加载对应默认表；
5. 更新默认表控制字段；
6. 主管重新识别起点井和终点井；
7. 主管重新计算端点深度；
8. 主管重新计算平均深度；
9. 重算全部非锁定结构层；
10. 井按井深与井下层规则重算；
11. 支管重新识别类型并应用特殊规则；
12. 重算工程量派生数据；
13. 返回完整模型给 UI。

最新规则下刷新不是“只补空白”，而是更新全部依赖值。对象身份和测量字段仍需有明确保护策略，例如井编号、自然标高不能被普通默认表覆盖。

### 13.4 按默认表重填

```text
用 SXMRB 中用户保存的当前类型默认表重建默认控制字段
→ 叠加对象图层元数据
→ 执行识别和依赖刷新
```

不能使用内置模板覆盖用户默认表。

支管特殊规则：

- 并埋、明管强制无结构层；
- 原土回填强制一层原土回填；
- 砼恢复使用用户默认结构层。

### 13.5 调换起终点

交换：

- `StartNode` ↔ `EndNode`；
- `StartDepth` ↔ `EndDepth`。

随后重算平均深度和结构层，但不立即写对象，确认后写入。

### 13.6 选起点井 / 选终点井

必须复用节点标注的吸附体验：

```text
隐藏属性窗口
→ 鼠标移动
→ 找到指针附近最近有效井
→ 临时引线从井中心指向鼠标
→ 有编号则显示编号预览
→ 单击确认
→ 不生成真实引线或文字
→ 返回属性窗口
```

候选井必须满足：

```text
父属性=井
分类=检查/沉泥井
```

选择后立即重算端点深度、平均深度和结构层。Esc 取消并保留原值。

### 13.7 结构层按钮

添加层：

- 当前层后添加；
- 默认高度 0；
- 默认不锁定；
- 默认不是管线层/井下层。

删除层：

- 删除当前层；
- 允许结构层为空，尤其是明管、并埋。

上移/下移：

- 顺序从上到下对应真实结构从上到下。

自动计算：

- 按对象类型计算；
- 保留错误结果；
- 显示警告；
- 不静默修正。

## 18. 主管工程量计算

符号：

```text
L = 有效管线长度
W = 开挖宽度
Havg = 平均开挖深度
Hr = 原路面结构层厚度
D = 管道外径
```

### 18.1 管身体积

若 `DeductPipeVolume=true`：

```text
Vpipe = π × (D / 2)² × L
```

否则为 0。

### 18.2 路面切缝

仅 `Hr > 0`：

```text
RoadCutting = L × 2
```

### 18.3 路面破碎

仅有原路面结构层时：

```text
RoadBreaking = L × W
```

### 18.4 拆除路面弃置

```text
RoadWaste = L × W × Hr
```

### 18.5 开挖沟槽土方

```text
Excavation = L × W × max(Havg - Hr, 0)
```

按 `ExcavationType` 分入机械或人工列。

### 18.6 结构层工程量

每层基本体积：

```text
LayerVolume = L × W × LayerHeight
```

按层名归类：

- 中粗砂垫层；
- 中粗砂回填；
- 碎石垫层；
- C25 砼恢复；
- 原土回填；
- C25 砼包管/包管层。

### 18.7 回填扣除管身体积

管身体积只从包含管身的回填或包管相关体积中扣除一次。

```text
SandBackfillVolume
= L × W × SandBackfillHeight - Vpipe
```

或：

```text
SoilBackfillVolume
= L × W × SoilBackfillHeight - Vpipe
```

禁止重复扣减。

### 18.8 无显式回填层

若结构层没有中粗砂回填和原土回填层：

```text
RemainHeight
= Havg
- C25恢复层高度
- 碎石层高度
- 管线垫层高度
```

小于 0 时统计可按 0 处理并记录警告。

根据 `BackfillType`：

- 原土 → 原土回填；
- 其他 → 中粗砂回填。

### 18.9 土方外运

通常：

```text
土方外运
= 拆除路面弃置
+ 机械/人工开挖土方
- 可回用原土回填量
```

正式结果必须使用 C# 计算服务返回值，前端不得自行组合。

## 19. 井工程量计算

符号：

```text
Aexc = ExcavationLength × ExcavationWidth
Awell = π × r²
Hwell = WellDepth
Hbelow = 井下层高度
Hr = 原路面结构层厚度
```

```text
井真实开挖总深度 Hreal = Hwell + Hbelow
```

### 19.1 井面积

```text
φ500 → r=0.25
φ700 → r=0.35
Awell = π × r²
```

### 19.2 路面切缝

有原路面结构层时：

```text
RoadCutting
= ExcavationLength × 2
+ ExcavationWidth × 2
```

### 19.3 路面破碎

```text
RoadBreaking = Aexc
```

### 19.4 拆除路面弃置

```text
RoadWaste = Aexc × Hr
```

### 19.5 基坑开挖土方

```text
Excavation
= Aexc × max(Hwell - Hr + Hbelow, 0)
```

按开挖方式分入机械或人工列。

### 19.6 井下垫层

```text
BelowWellLayerVolume = Aexc × Hbelow
```

归入哪一列由层名称决定。

### 19.7 井周回填

```text
Abackfill = max(Aexc - Awell, 0)
BackfillVolume = Abackfill × LayerHeight
```

井下层不属于井周回填高度。

### 19.8 承压盖板结构

按层名识别：

- 承压盖板碎石垫层；
- 承压盖板 C25 砼基础；
- C25 垫层。

常见体积：

```text
(Aexc - Awell) × LayerHeight
```

最终以统一计算服务为准。

### 19.9 数量项

设置承压盖板时：

```text
承压盖板数量 = 1
```

井盖类型有效时：

```text
井盖数量 = 1
```

### 19.10 沉泥井显示

Excel 中检查井类型包含“沉泥”时，该单元格字体标红。

## 26. Codex 开发约束

1. 不在前端复制工程量公式。

3. 不根据图层名单独判断对象类型。

12. 所有 CAD 写操作使用正确文档锁和事务。
13. 前端对象引用使用 Handle，并在执行前验证。

## 29. 最终数据链

```text
图层管理元数据
→ 对象类型与规格识别
→ 对象属性
→ 结构层
→ 端点/井关系
→ 深度派生
→ 工程量计算
→ 看板与正式表格
```

- 图层管理元数据是识别基础；
- 对象属性是持久化事实；
- 结构层是可编辑工程构造；
- 起终点深度和平均深度是派生值；
- 工程量结果是最终派生数据；
- UI 只是编辑和展示层。

任何新界面或重构都必须保持这条数据链只有一套 C# 业务实现。
