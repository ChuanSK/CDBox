# CDBox 悬浮球——同步中心与图纸检查中心开发设计文档

> 文档关系：本文件负责同步中心与图纸检查中心的业务模型、规则和流程；悬浮球 WPF 外壳、统一通知/提示/进度、CAD 生命周期和宿主架构，以《CDBox 悬浮球总体设计与开发规范》为准。旧版关于展开面板可选 WebView2 的建议不再作为当前实施方案。

## 1. 功能定位

CDBox 悬浮球不是传统“功能入口”，而是当前图纸的：

**状态指示器 + 异常提醒器 + 待办任务中心 + 同步控制中心。**

其核心目标不是让用户从悬浮球中启动大量工具，而是持续回答三个问题：

1. 当前图纸有没有问题？
2. 当前图纸有没有尚未同步的数据？
3. 哪些事情需要用户处理？

悬浮球默认保持轻量，不持续占据绘图区。

正常状态下仅显示一个小型悬浮图标；存在异常、待同步任务或警告时，通过颜色、角标和轻提示反馈状态。

# 2. 总体设计原则

## 2.1 用户必须知道系统做了什么

CDBox 不允许出现以下交互：

> 用户修改一个值，系统在没有明显反馈的情况下自动修改大量关联对象。

任何大范围属性联动必须满足至少一项：

- 用户主动执行；
- 用户提前开启“自动同步”；
- 系统明确显示此次同步影响；
- 操作可撤销；
- 操作结果可以查看。

## 2.2 自动计算与自动修改必须区分

例如：

管线垫层厚度变化后：

可以自动判断：

- 平均开挖深度需要重新计算；
- 结构层需要更新；
- 标注已经过期；
- 工程量已经过期。

但“发现需要更新”不代表必须马上修改。

因此系统统一采用：

> **检测 → 标记状态 → 根据同步策略执行**

而不是：

> 修改 → 立即无限级联修改

## 2.3 悬浮球只展示状态，不承担复杂编辑

悬浮球展开后可以：

- 查看问题；
- 查看同步任务；
- 定位对象；
- 执行同步；
- 执行批量修复；
- 忽略问题。

但复杂属性编辑仍进入：

- 属性编辑器；
- 对象编辑窗口；
- 设置页面；
- 独立 WebView2 页面。

# 3. 悬浮球状态设计

悬浮球建议拥有四种主状态。

## 3.1 正常

状态：

> 当前图纸无明显问题，无待同步任务。

表现：

- 普通 CDBox 图标；
- 无角标；
- 不主动提示。

## 3.2 待处理

存在：

- 待同步属性；
- 待刷新标注；
- 工程量缓存过期；
- 一般性图纸检查问题。

表现：

角标：

> 3

表示当前存在 3 类待处理任务，而不是 3 个实体。

避免：

> 238

这种容易造成压力且没有信息价值的巨大数字。

## 3.3 警告

例如：

- 管线缺少起终点；
- 井深数据异常；
- 管线平均深度计算失败；
- 图层没有父属性；
- 对象属性不完整；
- 标注关联对象已经删除。

悬浮球应使用明显但不刺眼的警告状态。

## 3.4 严重错误

例如：

- 大量对象属性损坏；
- 数据结构版本无法识别；
- 工程量计算无法继续；
- 对象引用循环；
- 同步过程中出现不可恢复错误。

此时悬浮球进入错误状态。

点击后优先显示严重错误，而不是普通任务。

# 6. 同步中心定义

同步中心负责管理所有：

> “数据已经发生变化，但相关数据尚未同步”的状态。

不建议单独再创建一个大型同步窗口。

同步中心直接作为悬浮球“任务”系统中的一种任务类型存在。

# 7. 同步对象分类

当前阶段建议支持以下同步类型。

## SyncType.Property

属性同步。

例如：

- 默认表 → 对象属性；
- 节点 → 管线；
- 管线 → 节点；
- 用户修改 → 派生属性。

## SyncType.Calculation

重新计算。

例如：

- 平均开挖深度；
- 结构层高度；
- 工程量数据；
- 管线真实深度。

## SyncType.Annotation

标注同步。

例如：

对象属性已经改变，但标注仍显示旧数据。

## SyncType.Relation

关系同步。

例如：

- 起点井；
- 终点井；
- 管线与节点绑定；
- 标注与对象绑定。

## SyncType.Display

图形显示同步。

例如未来：

- 图块显示；
- 图层；
- 对象样式；
- 状态显示。

# 8. 同步状态模型

每一个 CDBox 对象建议增加逻辑状态：

```
Clean
Dirty
Conflict
Error
Ignored
```

## Clean

对象数据与所有依赖数据一致。

## Dirty

对象或依赖已经发生变化，需要重新同步。

例如：

```
管线A

垫层厚度：
100 → 150

状态：
Dirty

影响：
平均深度
结构层
工程量
标注
```

## Conflict

出现冲突。

例如：

默认表：

```
垫层 = 150
```

但对象曾被用户手动修改：

```
垫层 = 120
```

系统不能确认是否覆盖。

此时不能自动同步。

必须进入：

```
Conflict
```

## Error

无法完成同步。

例如：

```
管线起点井不存在
```

## Ignored

用户主动选择：

> 忽略此次变化。

# 9. Dirty 标记机制

所有可能产生联动的数据修改，都不应直接负责执行完整联动。

正确流程：

```
属性修改
   ↓
ChangeDetector
   ↓
DependencyResolver
   ↓
产生 Dirty 标记
   ↓
SyncManager
```

例如用户修改：

```
井深
```

DependencyResolver 判断：

```
关联主管3条
关联支管2条

需要更新：
起点/终点深度
平均深度
结构层
工程量
标注
```

然后根据同步策略决定：

```
立即同步

或

创建待同步任务
```

# 10. 同步影响分析

任何同步执行前必须可以生成：


结构建议：

```
SyncImpact

AffectedObjects
AffectedProperties
AffectedAnnotations
AffectedCalculations

```

```
126

43

169

7
```

# 11. 自动同步策略

CDBox 不采用简单：

```
自动同步 ON/OFF
```

而建议分三级。

## 11.1 安全自动同步

默认开启。

只允许执行：

- 单对象；
- 小范围；
- 无冲突；
- 可逆；
- 明确属于派生属性的变化。

例如：

```
修改一个井深
→ 自动更新与其连接的几条管线
```

执行后显示 Toast：

```
已同步

1 个井
4 条管线
6 个相关数据
```

## 11.2 批量同步

默认需要确认。

例如：

```
默认表修改
```

影响：

```
126条主管
```

不能直接自动执行。

产生同步任务。

## 11.3 高风险同步

必须查看影响后确认。

例如：

- 大范围覆盖用户修改；
- 修改对象拓扑关系；
- 起终点重新识别；
- 大规模重新计算；
- 规则改变导致结构层变化。

# 13. 同步任务合并

必须避免：

```
主管1 Dirty
主管2 Dirty
主管3 Dirty
主管4 Dirty
...
```

在悬浮球显示成几百条任务。

应该自动合并。

例如：

```
主管垫层厚度需要同步

169个对象
```

而不是：

```
主管A垫层需要同步
主管B垫层需要同步
主管C垫层需要同步
...
```

合并依据：

```
Source
Property
SyncType
Rule
TimeWindow
```

# 15. 属性来源机制

同步系统建议同时开始加入属性来源信息。

字段：

```
ValueSource
```

建议：

```
Default
Manual
Calculated
Inherited
Imported
Unknown
```

例如：

```
主管A

垫层厚度 = 120

Source = Manual
```

修改默认值：

```
100 → 150
```

系统可以判断：

```
Source = Default
→ 可以更新

Source = Manual
→ Conflict
```

这将是以后稳定同步系统的重要基础。

# 16. 属性锁定

允许属性：

```
IsLocked
```

锁定之后：

任何规则同步不得修改该属性。

例如：

```
井深

2.35m

🔒
```

重新计算、默认表同步等均跳过。

任务报告：

```
同步完成

169个对象

已更新：161
已跳过锁定：8
```

# 17. 标注同步机制

标注必须进入统一同步体系。

标注不能继续作为完全独立的 CAD 图形存在。

建议每一个 CDBox 标注记录：

```
AnnotationId

TargetObjectId

AnnotationType

TemplateId

LastDataHash
```

对象数据变化后重新计算：

```
CurrentDataHash
```

如果：

```
CurrentDataHash != LastDataHash
```

则：

```
AnnotationState = Dirty
```

悬浮球产生任务：

```
12处标注需要更新
```

# 18. 标注同步执行

用户点击：

```
更新全部
```

仅更新标注内容。

原则：

**不得破坏用户手动调整过的标注位置。**

也就是说同步：

```
文字
字段
内容
```

不修改：

```
标注位置
引线位置
用户手动布局
```

除非标注本身结构发生变化。

# 19. 工程量同步

工程量建议采用：

```
Cache + Dirty
```

机制。

对象属性发生影响工程量的变化：

```
QuantityState = Dirty
```

悬浮球：

```
工程量需要重新计算
```

不要每修改一个属性就立即全图重新统计。

# 20. 图纸检查中心

图纸检查与同步中心虽然共用悬浮球入口，但逻辑必须独立。

同步回答：

> 数据之间是否一致？

图纸检查回答：

> 当前图纸是否存在异常？

# 23. 第一阶段图纸检查规则

当前 CDBox 功能已经足以实现以下规则。

## 23.1 图层检查

检测：

- 图层未设置父属性；
- 图层父类无效；
- 对象所在图层与对象类型冲突。

例如：

```
主管对象位于“注记”父类图层
```

## 23.2 对象分类检查

检测：

- 主管无法识别；
- 支管无法识别；
- 节点无法识别；
- 对象父属性为空。

## 23.3 属性完整性

主管：

检查：

- 管径；
- 材料；
- 起点井；
- 终点井；
- 平均深度；
- 垫层；
- 结构层。

支管：

根据支管类型检查不同字段。

井：

检查：

- 编号；
- 井深；
- 井规格；
- 井类型；
- 井盖；
- 材料。

# 24. 数据合法性检查

例如：

```
井深 <= 0
管径 <= 0
结构层高度 < 管径
平均开挖深度 < 管径
起点深度差异异常
```

具体阈值以后可以配置。

# 25. 管线关系检查

检查：

```
缺少起点井
缺少终点井
起终点相同
引用节点已经删除
节点不在合理距离
```

未来可以继续增加拓扑检查。

# 26. 标注检查

检查：

```
标注失去关联对象
标注内容已过期
对象存在但标注缺失
重复标注
```

第一阶段可优先实现：

```
失去关联
内容过期
```

# 27. 工程量检查

检查：

```
存在无法计算工程量的对象
```

例如：

```
缺少平均深度
结构层异常
公式计算错误
```

# 28. 检查执行时机

不建议每次对象变化都进行完整全图扫描。

采用两级机制。

## 实时轻量检查

修改对象时执行：

```
当前对象
直接关联对象
```

例如：

修改井：

只检查：

```
井
相关管线
相关标注
```

## 全图检查

以下情况执行：

```
用户点击“重新检查”
打开图纸后后台首次检查
执行大型同步之后
工程量输出之前
```

注意：

全图检查过程中不得阻塞 CAD 操作。

# 29. 自动修复

CheckRule 可提供：

```

```

例如：

```

```

```
自动更新
```

而：

```

```

可能无法安全自动解决。

只能：

# 31. CAD 对象定位

这是悬浮球必须实现的基础能力。

任何任务：

```
CheckIssue
SyncTask
```

只要包含 ObjectId，都应支持：

```
定位
```

定位操作建议：

1. 退出悬浮窗口焦点；
2. CAD Zoom 到对象；
3. 高亮对象；
4. 必要时闪烁一次；
5. 保持对象选中。

# 32. 临时高亮

建议实现统一：

```
ObjectHighlightService
```

供：

- 图纸检查；
- 同步影响预览；
- 工程量；
- 属性编辑；

共同使用。

避免每个功能单独写 Highlight。

# 35. Undo 设计

第一阶段可以依赖：

```
AutoCAD Transaction + Undo Mark
```

执行同步前创建统一 Undo 节点。

例如：

```
CDBox：同步主管垫层
```

用户 Ctrl+Z：

整个同步作为一个操作撤销。

不能出现：

```
Ctrl+Z 169次
```

# 36. 悬浮球数量统计

悬浮球角标统计：

```
TaskGroup Count
```

而不是：

```
Object Count
```

例如：

```
标注过期：86
管线缺少节点：3
默认值待同步：169
```

悬浮球显示：

```
3
```

# 37. 通知策略

系统不要频繁 Toast。

建议：

### 小范围自动同步

Toast：

```
✓ 已同步 4 个相关对象
```

### 大范围变化

悬浮球角标变化。

可短暂提示：

```
主管默认属性已变化

169个对象等待同步
```

### 普通检查问题

仅增加悬浮球角标。

### 严重问题

允许主动提示。

# 38. 悬浮球刷新机制

建议统一：

```
FloatingStatusService
```

它不参与业务计算。

只读取：

```
SyncManager
CheckManager
```

状态。

例如：

```
FloatingStatus
{
    PendingSyncCount
    WarningCount
    ErrorCount
    CriticalCount
}
```

悬浮球根据这些值渲染。

# 39. 推荐代码架构


# 40. CheckRule 接口

建议：

```
public interface ICheckRule
{
    string RuleId { get; }

    string Name { get; }

    CheckCategory Category { get; }

    IEnumerable<CheckIssue> Check(
        CheckContext context
    );
}
```

以后新增检查规则只需要新增 Rule。

不用修改检查中心本身。

# 41. SyncHandler 接口

建议同步同样采用扩展结构：

```
public interface ISyncHandler
{
    SyncType SyncType { get; }

    SyncImpact Analyze(
        SyncContext context
    );

    SyncResult Execute(
        SyncContext context
    );
}
```

以后：

```
属性
标注
工程量
用户自定义对象
```

都可以加入同步体系。

# 42. DependencyResolver

这是同步系统长期最重要的核心之一。

第一阶段不要设计成完整依赖图。

先使用显式规则。

例如：

```
井深变化
→ 管线起终点深度
→ 平均深度
→ 结构层
→ 工程量
→ 标注
```

配置为：

```
Well.Depth
    → Pipe.StartDepth
    → Pipe.AverageDepth
    → Pipe.Structure
    → Quantity
    → Annotation
```

# 43. 防止循环同步

必须从第一版防止：

```
井修改
↓
管线修改
↓
井修改
↓
管线修改
```

SyncContext 必须包含：

```
TransactionId
Source
VisitedObjects
VisitedProperties
```

同一个同步事务中：

同一个：

```
Object + Property
```

不得无限重复处理。

# 44. 同步事务

每次同步产生：

```
SyncTransaction
```

例如：

```
TransactionId:
20260812-001
```

所有：

```
属性变化
标注刷新
工程量失效
```

都属于同一个 Transaction。

方便：

- 日志；
- Undo；
- Debug；
- 历史查看。

# 45. 文档生命周期

# 48. WPF 悬浮球与宿主命令路由

悬浮球及轻量展开面板统一使用 WPF，不再为该界面创建 WebView2 实例。

UI 只通过结构化 ViewModel 命令调用 C# 宿主服务。为保持动作命名清晰，内部命令标识可沿用以下语义：

```text
floating.sync.open(taskId)
floating.sync.execute(taskId)
floating.sync.locate(taskId)

floating.check.refresh()
floating.check.open(issueId)
floating.check.locate(issueId)
floating.check.fix(issueId)
```

若复杂任务详情需要跳转现有 WebView2 工作台页面，可由 C# 宿主打开对应页面，并继续使用现有 Studio 路由，例如：

```
floating|sync|open|taskId
floating|check|open|issueId
```

无论操作来自 WPF 悬浮球还是工作台，真实的：

```
ObjectId
Transaction
Database
```

操作全部由 C# 宿主处理。

# 53. 单对象修改的最终目标流程

用户双击一个井。

修改：

```
井深

2.1 → 2.3
```

系统检测：

```
关联3条管线
```

属于安全的小范围同步。

自动执行：

```
起终点深度
平均深度
结构层
标注
```

Toast：

```
✓ 已同步3条关联管线
```

悬浮球不产生任务。

这样不会让正常编辑变得繁琐。

# 54. 产品层最终原则

CDBox 的属性联动以后统一遵守：

> **小修改自动联动，大修改先展示影响，有冲突必须交给用户。**

悬浮球则负责告诉用户：

> **这张图现在还有什么事情没有处理完。**

因此悬浮球不应该成为第二个菜单栏，也不应该成为属性侧边栏。

其长期定位应保持为：

```
CDBox
图纸状态中心
    │
    ├── 同步
    ├── 检查
    ├── 警告
    ├── 待办
    └── 操作历史
```

以后即使加入：

- 自定义工程量对象；
- 自定义属性；
- 自定义规则；
- 拓扑检查；
- 工程量校验；
- 图纸规范检查；

也全部能够挂接在这个体系中，而不需要重新设计悬浮球。
